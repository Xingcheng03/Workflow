FinAgent Dashboard

A six-agent, five-phase finance research workflow. Yahoo Finance provides the verified facts; Gemini handles reasoning, news summarization, and report writing; a dedicated Verifier agent cross-checks the final report against eight rules and triggers a revision when blocking issues are found.

1 · Overview

What this dashboard does

You type a stock ticker. Six agents collaborate to produce an investment brief, then an independent Verifier agent re-reads the brief alongside every upstream output and flags claims that aren't grounded in the data. If the report has blocking issues, the Report agent rewrites it and the Verifier checks again.

The core idea

Deterministic facts come from Yahoo. Reasoning comes from Gemini. Stock prices, fundamentals, earnings dates — none of that should be hallucinated. The Data agent fetches verified numbers; every other agent is constrained to use only what Data provides for numerical claims.

Why a Verifier?

LLMs drift. The synthesis step (Report) can quietly invent a number, invert a margin trend, or cite a news event that wasn't in the headlines. The Verifier replays the inputs and checks the report against eight rules. Blocking failures trigger one revision pass before the result is shown.

2 · The 6 agents

Each agent has a narrow lane

Boundaries are enforced by the prompts: Analysis can describe fundamentals but not assign a risk level; Risk can identify risks but not give a Buy/Hold rating; Report can synthesize but must source numbers from Data. The Verifier checks these boundaries explicitly.

Phase 5 loop in detail

5a · Verify v1. Verifier reads upstream + Report v1. If pass or warn only, the workflow ends.

5b · Revise (only if blocking). Report agent re-runs with the previous brief + the blocking issues as feedback. Grounding is disabled — the rewrite reasons on existing facts.

5c · Verify v2. One more verifier pass. The result (pass / warn / fail) is what the dashboard ultimately shows. No third revision attempt.

Cancellation

Esc or the X button aborts the in-flight AbortController. Any agent whose fetch was in flight gets its AbortError propagated; the workflow exits cleanly without partial state.

A synchronous re-entry guard prevents fast double-clicks on Run from spawning two parallel workflows that would orphan the first AbortController.

4 · The Verifier's 8 checks

Eight rules that catch report drift

Each rule is either blocking (triggers a revision) or warning (surfaced but doesn't trigger revision). Verifier output is deterministic JSON: { status, issues: [...] }.

1
Number fidelity Every number in the report must appear in DATA_METRICS within ±5% tolerance. Numbers in Analysis or Risk text don't count — those are restatements.
blocking
2
Recommendation × RiskLevel matrix A 4×5 truth table: Buy + High Risk = blocking, Avoid + Low Risk = blocking, Buy + Elevated = warning, Avoid + Moderate = warning. Hold/Watch + anything = OK.
b/w
3
Self-prediction language Phrases like "will reach $X" or "expected to recover" without third-party attribution are flagged. "Analysts target $X" is OK because it's attributed.
warning
4
Recommendation reasoning The recommendation must be grounded in Risk + Analysis findings. If the only justification is "analysts say buy" or analyst consensus alone, it's flagged.
warning
5
Bullet traceability Each bullet must connect to an upstream fact: a Data metric, a News headline, a Risk item, or an Analysis point. Bullets that introduce new claims are flagged.
warning
6
Upstream boundary lint Analysis containing risk-level language, or Risk containing recommendation language, is flagged. Catches agents drifting outside their lanes.
warning
7
News event fidelity Specific news events cited in the report must appear in NEWS_OUTPUT.news (or as a calendar event in DATA_METRICS). Citing a phantom event is blocking.
blocking
8
Thesis vs Analysis direction Thesis can't contradict Analysis: e.g. Analysis says "decelerating growth" but thesis says "accelerating growth story" → flagged. Same for valuation and margin direction.
warning
Why warnings don't trigger revision. The revision loop only fires on fail status (or any blocking issue). Warnings are surfaced in the report's Verifier strip so the user sees them, but a re-write is unlikely to fix them — they're often subjective wording calls.

6 · Data flow

From Yahoo to the rendered brief

The Data agent fetches three Yahoo endpoints in parallel, then downstream agents reason on a summarized projection of the state. The summarization step is intentional — it keeps prompt tokens down and prevents leaking transient fields (rawText, marketMeta source strings) into the LLM.

Source Endpoint What we extract
Yahoo Chart (intraday) /api/market-chart/<sym> OHLCV bars (intraday), regularMarketPrice, day/52w range, volume
Yahoo Chart (history) /api/market-chart/<sym>?range=6mo&interval=1d 6-month daily OHLCV, derives 6mo / 1mo return, drawdown
Yahoo quoteSummary /api/market-summary/<sym> 10 modules: summaryDetail, financialData, defaultKeyStatistics, calendar, earnings history/trend, recommendation trend, quarterly statements
Gemini API /v1beta/models/<model>:generateContent Per-agent payload (News / Analysis / Risk / Report / Verifier). Optional Google Search grounding.
Why the Vite-middleware proxy? Yahoo's quoteSummary endpoint requires a (cookie, crumb) pair obtained via a separate GET on fc.yahoo.com. Doing this from the browser fails on CORS. The proxy handles it server-side, with in-flight request deduplication, a refreshCrumb mutex (so concurrent first-time callers share a single auth round-trip), and a 15-second timeout.

7 · Tech stack

Choices, with reasons

React 18 + Vite 6 Fast dev loop, ESM-native build, proven SPA story.
Vitest + @testing-library/react Same loader as Vite (no transform mismatches). 201 tests across services, hooks, components.
JSDoc @typedef (no TypeScript) Modern editors give type hints from the JSDoc; the migration to .ts later is small.
Lucide-react icons Tree-shakable via barrel — only the 12 icons we import end up in the bundle.
SVG candlesticks (hand-rolled) No charting library. ~250 lines of SVG. Bundle saving vs. Recharts/lightweight-charts: 80–150 KB.
sessionStorage cache Per-tab, namespaced by model + grounding flag + prompt hash. 12 min for Gemini, 90 s for market data.
AbortController + AbortSignal.any() User cancel + 60 s per-attempt timeout merged into one signal per Gemini request.
ESLint flat config + GH Actions CI Lint, test, build run on every push and PR. No warnings allowed.

9 · Caching layers

Where state is stored and for how long

LayerWhereTTLKey
Yahoo summary sessionStorage (browser) 90 s finagent:market:<symbol>
Gemini response sessionStorage (browser) 12 min finagent:gemini:<model>:<g|j>:<promptHash>
Yahoo proxy in-flight in-memory (dev server) request lifetime chart:<sym>:<range>:<interval> / summary:<sym>
Yahoo crumb in-memory (dev server) until 401 single global, refresh under mutex
Cache key contains the model. Switching VITE_GEMINI_MODEL automatically invalidates the previous model's cached responses — they don't pollute the next run.

If Gemini quota is exhausted

A limit: 0 error means the API key has zero free-tier allowance for that model — switching models is the right fix:

  1. First try VITE_GEMINI_MODEL=gemini-2.0-flash — drop-in compatible
  2. Then gemini-2.0-flash-lite (separate quota pool)
  3. Then gemini-1.5-flash with VITE_GEMINI_USE_GOOGLE_SEARCH=false (1.5 uses an older tool format)
  4. Or generate a fresh key from a Google account that hasn't been linked to billing

11 · Deployment caveat

This project does not work as a static deploy

The dashboard hits /api/market-chart/... and /api/market-summary/.... Those routes are registered by server/yahooProxy.js against Vite's dev/preview server middleware. A bare dist/ static deploy (Netlify, Vercel, GitHub Pages, etc.) has no /api/* routes and would 404 every market request.

Doing it for real? The Yahoo proxy logic is already factored into a single file — lift server/yahooProxy.js into an Express, Fastify, or Cloudflare Workers handler with minimal changes. The Yahoo API contract, cookie+crumb handshake, in-flight dedup, and refresh mutex all transplant directly.
